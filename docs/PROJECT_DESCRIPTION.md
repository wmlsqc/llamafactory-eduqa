# 项目说明与简历素材

## 项目名称

基于 LLaMA-Factory 的教育问答模型优化与部署

## 项目简介

面向中学理科概念解释和解题答疑，基于 Qwen2.5-7B-Instruct 搭建教育领域模型优化流程，覆盖指令数据清洗、QLoRA 监督微调、独立评测、LoRA 权重合并、vLLM 推理服务和 Web 问答应用。通过统一命令行与运行记录管理实验配置、数据版本和部署结果。

## 设备配置

主配置为云端 **RTX 4090 24GB × 1、16 vCPU、64GB 内存、150GB SSD**，可在提供该型号的 AutoDL 或 RunPod 实例上运行。系统建议 Ubuntu 22.04、Python 3.11。训练使用 NF4 4-bit QLoRA、BF16、2048 序列长度、batch 1、梯度累积 8。此处为项目设备配置，实际训练设备由运行 manifest 自动记录。

## 可据实际参与情况采用的项目条目

- **数据与实验管理**：对理科问答进行字段校验、Unicode 归一化与重复检查，固定种子划分 450 条训练、50 条验证和 50 条独立测试数据；记录输入与输出 SHA-256，阻止训练和测试问题重合。
- **模型微调**：基于 LLaMA-Factory 编排 Qwen2.5-7B 的 NF4 QLoRA 监督微调，使用 rank 16 的 LoRA、梯度累积和梯度检查点，并按验证 loss 选择 checkpoint；保存实际硬件、训练配置和任务状态。
- **效果评估**：使用相同测试集与生成参数对比基座、微调模型，统计字符 F1、ROUGE-L 和文本精确匹配，导出人工评分表以检查回答正确性、完整性和指令遵循，并单独记录失败及截断回答。
- **推理与应用部署**：重新加载非量化基座合并 LoRA，使用 vLLM 提供推理接口；基于 FastAPI 构建支持多轮流式问答的中文网页，处理参数校验、鉴权、并发限制、超时与断连清理。
- **性能测试**：实现并发 SSE 压测，排除预热后统计首 Token 延迟、端到端延迟分位数和吞吐量；token 数仅采用服务端 usage，保存请求条件和原始结果便于复查。

## 结果填写方式

测试通过数量可引用 `docs/VERIFICATION.md` 的软件测试记录。训练时长、模型质量变化、显存、TTFT 和吞吐量应在云端实际运行后，从 `artifacts/runs`、`artifacts/eval` 和 `artifacts/benchmark` 填写。

软件功能已实现、推荐配置可解释，并不等于已取得 GPU 实验成绩。未完成训练前，描述“实现了训练/部署流程”可以对应代码；不要将配置参数、测试夹具或预期效果写成自己实测的优化收益。
